# AI 브랜드 제너레이터

브랜드 브리프(JSON)를 입력하면 LLM을 활용하여 **브랜드 네이밍, 슬로건, 브랜드 스토리, 컬러 팔레트, 로고 시안**을 단계적으로 생성하고 결과물을 파일로 저장하는 CLI 프로그램입니다.

---

## 1. 주요 기능

프로그램은 다음과 같은 5단계로 브랜드 결과물을 생성합니다.

1. **브랜드 네이밍**

   * 한글 브랜드명 후보 3~5개 생성
   * 각 후보의 영문 브랜드명(`name_en`) 생성
   * 이름의 의미 및 유래(`meaning`) 생성

2. **슬로건**

   * 슬로건/태그라인 3개 생성

3. **브랜드 스토리**

   * 업종, 타겟, 키워드, 톤앤매너를 반영
   * 브랜드의 탄생 배경, 철학, 비전을 포함한 스토리 생성

4. **컬러 팔레트**

   * 메인 컬러 1개 생성
   * 서브 컬러 2~3개 생성
   * HEX 코드 형식 검증
   * 컬러 팔레트를 PNG 이미지로 저장

5. **로고**

   * 서로 다른 스타일의 로고 시안 3개 생성
   * 생성된 이미지를 PNG 파일로 저장

생성 과정에서 오류가 발생하더라도 가능한 경우 다음 단계로 진행하며, 오류 내용은 `brand_result.json`의 에러 기록에 저장합니다.

---

## 2. 실행 흐름

전체적인 실행 과정은 다음과 같습니다.

```text
브랜드 브리프 JSON 입력
        │
        ▼
   브리프 검증
        │
        ▼
┌───────────────────┐
│ 1. 브랜드 네이밍   │
└─────────┬─────────┘
          ▼
┌───────────────────┐
│ 2. 슬로건 생성     │
└─────────┬─────────┘
          ▼
┌───────────────────┐
│ 3. 브랜드 스토리   │
└─────────┬─────────┘
          ▼
┌───────────────────┐
│ 4. 컬러 팔레트     │
└─────────┬─────────┘
          │
          ▼
     컬러 PNG 저장
          │
          ▼
┌───────────────────┐
│ 5. 로고 시안 생성  │
└─────────┬─────────┘
          ▼
     결과 JSON 저장
          │
          ▼
       ./output
```

LLM 응답이 요구된 형식에 맞지 않는 경우에는 검증 후 수정 요청을 통해 다시 생성하며, API 또는 단계 실행에 실패한 경우 재시도 및 지수 백오프를 적용합니다.

## 3. 필요한 환경

* Python 3.x
* OpenAI API 사용을 위한 API 키
* 이미지 생성 API 사용을 위한 API 키
* 인터넷 연결

필요한 Python 패키지는 다음과 같습니다.

```bash
pip install openai requests matplotlib
```

---

## 4. API 키 설정

프로젝트 폴더에 `.env` 파일을 생성합니다.

예:

```env
OPENAI_API_KEY=본인의_OpenAI_API_키
IMAGE_API_KEY=본인의_이미지_API_키
IMAGE_API_BASE_URL=https://copa.codyssey.kr
```

이미지 API가 `OPENAI_API_KEY`를 사용하는 경우 `IMAGE_API_KEY`는 생략할 수 있습니다.

`.env` 파일에는 실제 API 키가 포함되므로 GitHub 등의 공개 저장소에 업로드하지 않는 것을 권장합니다.

## 5. 브리프 JSON 작성

프로그램 실행 시 브랜드 브리프 JSON 파일의 경로를 입력합니다.

필수 필드는 다음과 같습니다.

* `industry`: 업종
* `target`: 주요 타겟
* `keywords`: 브랜드 관련 키워드

선택 필드는 다음과 같습니다.

* `tone`: 톤앤매너
* `competitors`: 경쟁 브랜드
* `notes`: 추가 요구사항

### 입력 예시

```json
{
  "industry": "친환경 생활용품",
  "target": "20~30대 환경에 관심이 많은 소비자",
  "keywords": [
    "친환경",
    "일상",
    "간결함"
  ],
  "tone": "따뜻하고 친근한",
  "competitors": [
    "브랜드A",
    "브랜드B"
  ],
  "notes": "일상에서 쉽게 사용할 수 있는 이미지를 강조"
}
```

## 6. 프로그램 실행

터미널에서 다음 명령어를 실행합니다.

```bash
python brand_generator.py
```

실행 후 브리프 JSON 경로를 입력합니다.

```text
=== AI 브랜드 제너레이터 ===

브리프 JSON 파일 경로를 입력하세요: ./brief.json
출력 폴더 경로를 입력하세요 (엔터 = ./output):
```

출력 폴더를 입력하지 않고 Enter를 누르면 기본적으로 `./output` 폴더에 결과가 저장됩니다.

---

## 7. 생성 결과

정상적으로 실행되면 출력 폴더에 다음과 같은 파일이 생성됩니다.

```text
output/
├── brand_result.json
├── color_palette.png
├── logo_01.png
├── logo_02.png
└── logo_03.png
```

### `brand_result.json`

생성된 브랜드 결과와 오류 기록이 JSON 형태로 저장됩니다.

구조 예시는 다음과 같습니다.

```json
{
  "brief": {},
  "naming": [],
  "slogan": [],
  "story": "",
  "color_palette": {
    "main": "#RRGGBB",
    "sub": [
      "#RRGGBB",
      "#RRGGBB"
    ]
  },
  "color_palette_image": "output/color_palette.png",
  "logo_paths": [
    "output/logo_01.png",
    "output/logo_02.png",
    "output/logo_03.png"
  ],
  "errors": []
}
```

오류가 발생한 경우 오류 기록에 단계명, 오류 메시지, 발생 시간이 저장됩니다.

예:

```json
"error": [
  {
    "step": "컬러 팔레트",
    "message": "컬러 팔레트 응답이 올바른 JSON 형식이 아닙니다.",
    "timestamp": "2026-08-31T16:00:00"
  }
]
```

## 8. 오류 처리 및 재시도

LLM 생성 단계에서는 응답 결과를 검증합니다.

예를 들어 네이밍의 경우:

* 결과가 JSON 리스트인지 확인
* 후보가 3~5개인지 확인
* `name`, `name_en`, `meaning` 필드가 존재하는지 확인

슬로건은:

* JSON 리스트인지 확인
* 정확히 3개인지 확인
* 각 항목이 비어 있지 않은 문자열인지 확인

컬러 팔레트는:

* `main` 컬러가 존재하는지 확인
* `sub` 컬러가 2~3개인지 확인
* HEX 코드 형식인지 확인

검증에 실패하면 수정 요청을 포함하여 다시 생성합니다.

또한 단계 실행 중 오류가 발생하면 최대 3회까지 재시도하며, 재시도 사이에는 지수 백오프 방식으로 대기합니다.

```text
1차 실패
  ↓
1초 대기
  ↓
2차 시도
  ↓
2차 실패
  ↓
2초 대기
  ↓
3차 시도
  ↓
최종 실패 → 오류 기록 → 다음 단계 진행
```

## 9. 파일 구성

현재 프로젝트의 핵심 프로그램은 다음 파일입니다.

```text
project/
├── brand_generator.py
├── .env
├── .env.example
├── brief.json
└── output/
```

`brand_generator.py` 하나에서 브리프 입력, LLM 호출, 결과 검증, 이미지 생성 및 저장, 결과 JSON 저장을 수행합니다.

---

## 10. 보안 주의사항

API 키는 소스 코드에 직접 작성하지 않고 `.env`를 통해 관리합니다.

`.env` 파일을 Git에 포함하지 않도록 `.gitignore`에 다음 항목을 추가하는 것을 권장합니다.

```gitignore
.env
__pycache__/
output/
```

API 키가 포함된 파일을 공개 저장소에 업로드하지 않도록 주의해야 합니다.

## 11. 프로그램의 전체 처리 구조

```text
입력
 │
 └─ brand brief JSON
       │
       ▼
   브리프 검증
       │
       ▼
   LLM 생성 단계
       │
       ├─ 네이밍
       ├─ 슬로건
       ├─ 스토리
       └─ 컬러
       │
       ▼
   응답 검증
       │
       ├─ 정상 → 다음 단계
       │
       └─ 실패 → 수정 요청 / 재시도
       │
       ▼
   시각 결과 생성
       │
       ├─ color_palette.png
       └─ logo_01~03.png
       │
       ▼
   brand_result.json
       │
       ├─ 생성 결과
       └─ error 기록
```

이 프로그램은 하나의 브랜드 브리프를 입력으로 받아 텍스트 기반 브랜드 요소와 시각적 브랜드 요소를 자동으로 생성하고, 최종 결과물을 하나의 출력 폴더에 정리하는 것을 목표로 합니다.
